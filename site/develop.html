How TempAR Works

TempAR is a single PSP kernel-mode plugin (.prx) loaded via the plugin loader (seplugins). It hooks into a running game or homebrew's memory space, draws an in-game menu over the game's own framebuffer, and applies cheat codes (CWCheat or PSP Action Replay format) to memory once per loop iteration. There's no multi-process architecture, no IPC — everything happens inside that one module.

Written in C (with some hand-written MIPS assembly), targeting the PSP MIPS toolchain via PSPSDK. Two binaries are produced from the same source tree: a full build (tempar.prx) and a lite build (tempar_lite.prx) for POPS/memory-constrained modes, differentiated by preprocessor flags.

Major Subsystems
Cheat Engine — loads, saves, and executes CWCheat/PSPAR/PSPAR Extended code types against live game memory every loop tick. Menu / UI — a blocking state machine drawn directly onto the PSP's debug-screen text console, no custom graphics engine.
Memory Search — file-backed exact/unknown-value search that survives across menu sessions and reboots. MIPS Disassembler — a vendored PSPLINK-derived instruction decoder powering the browser/decoder screen.
Building From Source

No local PSP toolchain install required — everything runs through Docker:

docker run -it -v "${PWD}:/src" -w "/src" pspdev/pspsdk make release

This produces both PRX builds packaged as a .zip in a build folder. CI builds and publishes releases automatically via GitHub Actions on every tag push.
